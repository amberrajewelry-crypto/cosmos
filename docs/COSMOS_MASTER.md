# БЛОК 0. ПАСПОРТ

**Что это.** Веб-продукт, который показывает человеку настоящий космос,
действующий на него и внутри него прямо сейчас и в момент его рождения.
Всё вычисляется из четырёх входов: широта, долгота, высота, время.

**Тезис.** *Космос не вокруг тебя, а внутри тебя.*

**Отличие.** Тот же эмоциональный регистр, что у астрологии, при нулевой лжи.
Каждое число размечено по способу получения: вычислено / оценено / измерено
не здесь / миф.

**Для кого.** Не для астрологов и не для астрономов. Для человека, которому
интересно про себя, и который не хочет, чтобы его обманывали.

**Два лица.** «Сейчас» — живая 3D-сцена. «Карта рождения» — персональный
артефакт в канонической круглой форме.

**Ключевая механика.** Зум в обе стороны: наружу — галактики, внутрь — атомы,
выплавленные в этих галактиках. На обоих концах один и тот же космос.

**Варианты имени** (нужно выбрать):

| Имя | За | Против |
|---|---|---|
| **Внутри** | прямо тезис, коротко, запоминается | общее слово, трудно в поиске |
| **Реликт** | реликтовое излучение — древность внутри тебя | требует объяснения |
| **Настоящая карта** | SEO-дружелюбно, прямой захват запроса | длинновато, описательно |
| **Апекс** | точка, куда летим сквозь космос | узкий термин |

# БЛОК 1. СМЫСЛ

## 1.1 Что происходит с человеком

Он живёт внутри океана сил, которых не чувствует. Над ним стоит Солнце
в конкретной точке неба. Луна тянет его тело. Магнитные линии протыкают его
насквозь. Каждую минуту его прошивают мюоны, рождённые в верхней атмосфере.
И он, «сидящий неподвижно», несётся сквозь пространство на 370 км/с.

Всё это абсолютно реально и абсолютно невидимо.

## 1.2 Четыре типа невидимости

Это костяк высказывания, а не украшение:

1. **Слишком постоянное** — гравитация, магнитное поле. Исчезают из восприятия,
   как гул холодильника.
2. **Слишком редкое и мелкое** — мюон сквозь тело, вспышка.
3. **Слишком большое** — движение вокруг центра Галактики.
4. **Не вещь, а система отсчёта** — 370 км/с относительно реликта.
   Нельзя увидеть, можно только вычислить.

## 1.3 Позиция: контр-астрология

Астрология эксплуатирует древний голод — «космос воздействует лично на меня» —
и кормит его выдумкой. Проект берёт тот же голод и отвечает настоящей физикой.

**Напряжение, определяющее всё:** астрология даёт смысл, потому что врёт;
честные данные дают правду, но рискуют быть холодными. Задача эмоциональная,
не техническая.

Три рычага: **присутствие** (это про меня, здесь, сейчас) · **внутренность**
(оно во мне, а не снаружи) · **красота**.

## 1.4 Формула смешения с астрологией

**Астрология не выдумала математику — она выдумала смысл.**

| Элемент | Что это на самом деле |
|---|---|
| Асцендент, MC | реальные точки эклиптики — вычисляются точно |
| Аспекты | настоящие угловые расстояния |
| Ретроградность | реальное явление, параллакс |
| Фазы, узлы | реальная механика, узлы дают затмения |
| Дома | геометрия реальная, назначение выдумано |
| Знак зодиака | реален, но сдвинут прецессией на ~24° |
| «Влияние на судьбу» | **выдумка** |

Забираем **весь аппарат и всю форму**. Заменяем **только последнюю строку** —
интерпретацию.

## 1.5 Пять тегов честности

| Тег | Смысл |
|---|---|
| `[ТОЧНО]` | выведено из измеренного положения |
| `[ОЦЕНКА]` | модельная оценка |
| `[ГЛОБ]` | измерено, но не в твоей точке |
| `[СПОРНО]` | данные неоднозначны |
| `[МИФ]` | утверждение без основания, показано рядом с реальностью |
| `[ИНТЕРПРЕТАЦИЯ]` | текст, порождённый языковой моделью |

**Честность — это тип данных, а не комментарий.** Показать число мимо
структуры `Value` технически невозможно.

## 1.6 Единственная линия

Не утверждаем, что небесные тела влияют на характер, судьбу или события.
Как только одно ложное утверждение подано как истинное, тег `[ТОЧНО]`
перестаёт что-либо значить — и обесценивает остальные 91 параметр.

# БЛОК 2. ПРОДУКТ

## 2.1 Два лица

| | «Сейчас» | «Карта рождения» |
|---|---|---|
| Форма | 3D-объём, зум в обе стороны | плоский круг, каноническая карта |
| Поведение | тикает, живёт | застыла навсегда |
| Живые слои | работают | честно гаснут: «исторически недоступно» |
| Эксклюзив | ~20 слоёв (API, прогноз) | ~10 слоёв (дельта, сарос, звёзды года) |
| Выход | экран, состояние | PNG/PDF, ссылка, печать, шеринг |

Общее ядро — **~65 параметров**. Разделять на два проекта нельзя: блок `[МИФ]`
работает только в натальном контексте, живая физика — только в «сейчас».

## 2.2 Три сценария

**Смотреть** — живая сцена, зум по масштабам, слои реагируют на реальные данные.

**Узнать себя** — карта рождения: снимок + персональный нарратив из настоящих
фактов + призрачный астрологический слой с сопоставлением.

**Спросить** — свободный вопрос, на который отвечают **твоими** числами.
«Почему я легче на экваторе» → ответ с твоей широтой и твоей массой.

## 2.3 Срез первой версии — 12 параметров

Не «MVP по спеке», а двенадцать, где каждый несёт свою идею, ни один
не дублирует другой, и все **визуальны** (не только число):

| # | Параметр | Идея |
|---|---|---|
| 1 | Атомы по происхождению | **ядро тезиса**: 62 % тебя старше звёзд |
| 2 | Реликтовые фотоны внутри тела (29 млн) | древность внутри |
| 3 | Своя радиоактивность (7000 распадов/с) | ты сам источник |
| 4 | Нейтрино: днём в грудь, ночью в ноги | проницаемость |
| 5 | Мюоны сквозь тело | + доказывают СТО собой |
| 6 | Градиент времени голова/ноги | пространство-время внутри тебя |
| 7 | Небо: Солнце, Луна, планеты | основа, узнавание |
| 8 | Магнитные линии по реальному наклонению | поле протыкает |
| 9 | 4+1 вектор скорости (включая время) | покой — иллюзия |
| 10 | Длина тени | **проверяемость** |
| 11 | Реальное созвездие vs знак | контр-астрология |
| 12 | Звёзды года рождения | личное, невозможно подделать |

Остальные 80 живут в контент-базе, доступны через вопрос, но не грузят интерфейс.

## 2.4 Первые десять секунд

Критично: человек не должен упереться в форму ввода.

```
0 с   Тёмный экран. Фигура. Внутри неё медленно проступают точки.
2 с   Одна фраза: «Прямо сейчас внутри тебя 29 миллионов фотонов,
      родившихся через 380 000 лет после Большого взрыва».
5 с   Появляется вторая: «62 % твоих атомов старше любой звезды».
8 с   «Показать, что происходит именно с тобой?» → гео + дата.
```

До ввода данных работает всё, что не зависит от точки: состав тела, потоки,
масса-энергия. Ценность показана **до** того, как что-то попросили.

## 2.5 Единица контента — карточка параметра

Всё, что показывается человеку, имеет одну форму:

```
┌──────────────────────────────────────┐
│  ЧИСЛО + единица         [ТЕГ]       │  ← моноширинный
│  Название параметра                  │
│  ─────────────────────────────────   │
│  Одна фраза объяснения               │  ← антиква
│  Источник · возраст данных           │
│  [спросить дальше]  [где проверить]  │
└──────────────────────────────────────┘
```

Из этой карточки собирается панель, круг натальной карты и экспорт.
Одна форма — три применения.

## 2.6 Чего НЕ делаем

- Не предсказываем события и не даём советов.
- Не утверждаем влияние на характер, здоровье, судьбу.
- Не собираем базу дат рождения (всё считается в браузере).
- Не строим социальную сеть, ленту, комментарии.
- Не делаем приложение до того, как работает веб.

## 2.7 Метрики

Трафик — не главная. Главные:

| Метрика | Почему |
|---|---|
| Время на странице | проект должен залипать, а не пролистываться |
| Доля дошедших до карты рождения | сработал ли переход от любопытства к личному |
| Доля задавших вопрос LLM | работает ли глубина |
| Доля вернувшихся через 7 дней | есть ли причина возвращаться |
| Шеры карты рождения | сработал ли артефакт |
| Доля дошедших до блока `[МИФ]` | доходит ли тезис |

# БЛОК 3. ТЕХНИЧКА

## 3.1 Стек

```
Vite + TypeScript
three                 — 3D
astronomy-engine      — эфемериды, затмения, геоцентрические расстояния
geomagnetism (WMM)    — склонение, наклонение, напряжённость
luxon                 — время и часовые пояса (историческая TZ-база)
satellite.js          — спутники (позже)
```

Живые источники: NOAA SWPC · Open-Meteo · GWOSC · USGS · Celestrak.
Бэкенд не нужен, кроме тонкого прокси, **если** NOAA закроет CORS.

## 3.2 Архитектура — пять слоёв

```
        ui/  ←──────→  store  ←──────→  scene/
                         ↑
              ┌──────────┼──────────┐
              ↓          ↓          ↓
         compute/     live/       llm/
        (числа,     (числа,    (только слова,
         точно)      API)       на вход — числа)
```

**Правила зависимостей — однонаправленные, нарушать нельзя:**

- `compute/` — чистые функции. Ноль three.js, DOM, fetch. Тестируются числом.
- `live/` — async, кэш, статусы. **Никогда не бросает наружу** — ошибка
  превращается в `status:'error'`, слой гаснет, сцена живёт.
- `llm/` — принимает `Value[]`, возвращает текст. Не ходит в сеть за данными.
- `scene/` — только рисует. Ничего не считает и не грузит.
- `ui/` — форма, панель, диалог. Ничего не считает.

## 3.3 ЖЕЛЕЗНОЕ ПРАВИЛО: LLM не вычисляет

Модель галлюцинирует числа — это её природа. Одно выдуманное значение
обесценивает тезис.

```ts
interface LLMContext {
  values: Value[];        // ВСЕ числа, с тегами и источниками
  focus?: LayerId;        // на что человек смотрит
  zoomLevel: ScaleLevel;
  mode: 'now' | 'birth';
  depth: 'ребёнок' | 'обычно' | 'физик';
  question?: string;
}
```

В системном промпте: «Если числа нет во входных данных — скажи, что не знаешь.
Не оценивай, не вспоминай, не выводи». Ответ возвращает список `Value.id`,
на которые опирался, — интерфейс подсвечивает эти слои в сцене.

## 3.4 Типы

```ts
type Tag = 'ТОЧНО'|'ОЦЕНКА'|'ГЛОБ'|'СПОРНО'|'МИФ'|'ИНТЕРПРЕТАЦИЯ';
type Status = 'ok'|'loading'|'error'|'unavailable';

interface Value {
  id: LayerId;
  label: string;
  value: number | null;   // null = нет данных, слой гаснет
  unit: string;
  tag: Tag;
  source: string;         // «WMM2025», «NOAA SWPC», «astronomy-engine»
  status: Status;
  computedAt: number;
}
```

## 3.5 Система координат — фиксируется раз и навсегда

Место, где «примерно» = небо визуально врёт.

- Фигура в `(0,0,0)`, `+Y` — зенит
- `−Z` — Север, `+X` — Восток (правая тройка)
- Азимут от Севера к Востоку

```
x =  R · cos(A) · sin(Az)
y =  R · sin(A)
z = −R · cos(A) · cos(Az)
```

**Все** слои используют только эту функцию. Никаких локальных разворотов.

## 3.6 Производительность

- Небесные расчёты — раз в секунду, не каждый кадр.
- Живые API — TTL-кэш: Kp 3 ч, ветер 5 мин, аврора 30 мин, погода 1 ч,
  GWOSC/USGS раз в сутки. Дедуп одновременных запросов.
- OVATION (аврора) — глобальная сетка, тяжёлая: интерполировать к точке
  и жёстко кэшировать.
- Частицы — инстансинг, не отдельные меши.
- Бюджет кадра: сцена должна держать 60 fps на среднем телефоне.

## 3.7 Приватность — архитектурное решение

**Всё считается в браузере. Координаты и дата рождения не уходят на сервер.**
Прокси (если понадобится) не видит координат пользователя.

Это и этика, и сильнейший довод против астрологических сервисов,
собирающих базы дат рождения.

## 3.8 Верификация — обязательство, а не тест

Ошибка в 3 % в длине тени рушит весь тезис. Сверка **до релиза**:

| Что | Против чего |
|---|---|
| Небо, эфемериды | JPL Horizons |
| Магнитное поле | калькулятор NOAA/NCEI |
| Восходы, закаты, затмения | timeanddate |
| Прилив | опубликованные модели земного прилива |

Отклонения документируются. **Исходники открыты** — проект, говорящий
«не верь, проверь», обязан показывать формулы.

## 3.9 Устойчивость и честность данных

- Слой без данных гаснет, панель показывает `[—]` и «источник недоступен».
- У каждого живого значения — метка времени и визуальное выцветание
  по мере устаревания. Кэш 15 минут значит «15 минут назад», и это видно.

## 3.10 Доступность

- Тег кодируется **фактурой**, не цветом (дальтонизм).
- `prefers-reduced-motion` обязателен — 3D-движение вызывает вестибулярные
  проблемы.
- Панель читается скринридером: это в первую очередь данные.

## 3.11 Тесты

- Юнит-тесты на `compute/` — против эталонных значений (см. 3.8).
- Скриншот-регрессии сцены через Playwright: небо не должно «переехать»
  после рефакторинга.
- Мок-режим для `live/`: сцена собирается без сети.

# БЛОК 4. ВИЗУАЛ

## 4.1 Главный образ: тело как окно, а не силуэт

Не человек **на фоне** звёзд. Человек, **внутри которого** звёзды.

Полупрозрачный объём, наполненный светящимися точками. Это не двойная
экспозиция как приём — это данные: 29 миллионов реликтовых фотонов,
атомы, раскрашенные по эпохе рождения, вспышки распада калия-40.

Снаружи — оболочки полей и небо, но взгляд ведут **внутрь**.

## 4.2 Зум в обе стороны — тезис доказан геометрией

```
кварк ← ядро ← атом ← клетка ← ТЕЛО → комната → горизонт →
                                     → магнитосфера → орбита → галактика → Вселенная
```

Наружу — галактики. Внутрь — атомы, выплавленные в этих галактиках.
**На обоих концах один и тот же космос.** Объяснять словами не нужно.

Это же решает проблему 92 параметров: 10–15 на уровень вместо стены чисел.

## 4.3 Цвет = происхождение вещества

Смысловая шкала, а не палитра:

| Цвет | Что | Возраст |
|---|---|---|
| Глубокий индиго / фиолет | водород Большого взрыва (62 % атомов) | 13.8 млрд лет |
| Тёплое золото | C, N, O — выплавлены в звёздах | миллиарды лет |
| Красный | железо — из сверхновых | — |
| Платина / белый | золото, йод — слияния нейтронных звёзд | — |

Фигура, раскрашенная по происхождению атомов, — готовый главный кадр проекта.

## 4.4 Фактура = честность

| Тег | Фактура |
|---|---|
| `[ТОЧНО]` | сплошное, плотное, чёткий край |
| `[ОЦЕНКА]` | полупрозрачное, мягкий край, лёгкий шум |
| `[ГЛОБ]` | только контур, заливки нет |
| `[СПОРНО]` | пунктир |
| `[МИФ]` | призрачное, тонкая белая линия, как мел |

Освобождает цвет под физический смысл и решает дальтонизм.

## 4.5 Эстетический ключ: XVII век, до расхождения

Атласы Целлариуса («Harmonia Macrocosmica», 1660), Гевелия, Байера.
Гравюры, где небесная механика нарисована золотом и орнаментом.
Кеплер составлял гороскопы и открывал законы движения одной рукой.

**Это точка, где наука и астрология ещё были одним делом.** Не склеивать
две эстетики — вернуться туда, где они не разошлись.

Практически: фон — глубокий индиго с градиентом (не чёрный, чёрный убивает
глубину) · золотая и медная линия · тонкая гравюрная штриховка ·
концентрические круги и градуированные шкалы по краю.

## 4.6 Типографика — место смешения

- **Заголовки и нарратив** — антиква с засечками. Регистр карты рождения,
  старинной гравюры, обращения к человеку.
- **Числа, единицы, источники** — моноширинный гротеск. Регистр прибора.

Контраст двух гарнитур **сам является высказыванием**: поэзия и измерение
в одном документе, и видно границу.

## 4.7 Форма карты рождения

Канонический круг. Человек, пришедший по запросу «натальная карта», должен
**мгновенно узнать форму** — узнавание есть доверие. Наполнение честное:
реальные alt/az, настоящий асцендент и MC, настоящие углы аспектов.

## 4.8 Ключевой момент продукта — поворот прецессии

Переход между астрологической и настоящей картой делается **не переключателем,
а поворотом**: круг знаков плавно проворачивается на ~24° и садится
на реальные созвездия.

Человек своими глазами видит расхождение, накопленное за две тысячи лет.
Одна анимация вместо страницы объяснений.

## 4.9 Движение

Медленное, дыхательное, без рывков. Земля дышит приливом. Частицы дрейфуют.
Аура бури пульсирует с периодом в секунды, а не мигает.

## 4.10 Масштаб и нормировка

Купол, скорости (347 … 370 000 м/с) и тело несопоставимы.

**Правило: любой визуальный масштаб, не равный физическому, обязан иметь
подпись с настоящим значением.** Скорости — лог-шкала, и в легенде прямо
сказано: «длина стрелки = log(v), не v».

# БЛОК 6. ПЛАН И РИСКИ

## 6.1 Порядок работы

**До кода:**

1. Выбрать имя.
2. Вордстат → частотки в ядро → финальные приоритеты.
3. Визуальный язык: 5 фактур честности, палитра происхождения, две гарнитуры,
   макет карточки параметра, композиция круга.
4. Верификация первых 12 формул против эталонов. Без этого нет права на `[ТОЧНО]`.
5. Контент-база (Airtable): 92 параметра × формула, число, источник, тег,
   3 уровня текста, статус верификации.

**Код:**

6. Скелет: Vite + three + `coords.ts` + фигура + зум в обе стороны.
7. Слои 1–12 по одному, каждый с текстом из базы.
8. LLM-слой: контракт, промпт с запретом на числа, предгенерация 12×3.
9. Натальное лицо: круг, нарратив, `[МИФ]`, поворот прецессии, экспорт.
10. Программатик, публикация исходников, аналитика.

# БЛОК 7. ОБРАТНАЯ СВЯЗЬ

## 7.1 Принцип: фидбек не ломает приватность

Проект обещает, что координаты и дата рождения не уходят на сервер.
Система обратной связи обязана это соблюдать — иначе обещание пустое.

**Три правила:**

1. Никакая отправка не содержит координат и даты рождения **по умолчанию**.
2. Если для воспроизведения ошибки нужны входные данные — спрашиваем явно:
   «приложить твои координаты и время? они нужны, чтобы повторить расчёт».
   Отказ не блокирует отправку.
3. Аналитика — самостоятельно размещённая (Plausible / Umami), без
   персональных идентификаторов и кросс-сайтового трекинга.
   Никакого Google Analytics.

## 7.2 Четыре уровня сбора

| Уровень | Что | Усилие человека |
|---|---|---|
| **Пассивный** | что смотрят, докуда зумят, где уходят, что шерят | нулевое |
| **Микро** | одна кнопка на карточке параметра | одно нажатие |
| **Активный** | форма: свободный отзыв, репорт ошибки | минута |
| **Глубокий** | разговор с LLM, интервью | добровольно |

## 7.3 Канал «число неверно» — критичный для этого проекта

Обычному продукту это не нужно. Здесь — необходимо: тег `[ТОЧНО]`
даёт право требовать точности, и любой физик, астроном или просто
внимательный человек должен иметь **одну кнопку**, чтобы сказать
«у вас тут ошибка».

На каждой карточке параметра:

```
[ спросить дальше ]  [ где проверить ]  [ ⚑ число неверно ]
```

По нажатию — короткая форма:

```
Какое значение ты ожидал?          [        ]
Чем проверял? (источник)           [        ]
Приложить твои входные данные?     [ ] да
```

Уходит в трекер, привязывается к `LayerId`. Одно подтверждённое
расхождение важнее сотни отзывов о дизайне.

## 7.4 Краудсорс верификации ⭐

Проект уже просит человека выйти и проверить: тень линейкой, высоту
Полярной глазом, склонение компасом. Логично **собрать результаты этих
проверок** — и получится распределённая верификация из тысяч точек мира.

```
Ты измерил свою тень. Сошлось?
[ да ]   [ разошлось на… ]   [ не понял, как мерить ]
```

Что это даёт: если в одном регионе систематически «разошлось» — значит,
где-то ошибка в модели или в часовых поясах, и она видна на карте.
Ни один конкурент такого сделать не может, потому что никто не просит
проверять.

Приватность: отправляется только результат и часовой пояс, не координаты.

## 7.5 Вопросы к LLM — карта дыр в интерфейсе

**Самый ценный источник и самый недооценённый.** Каждый вопрос человека
означает, что интерфейс чего-то не показал.

- 200 человек спросили «почему ночью нейтрино снизу» → это надо показывать
  в сцене, а не прятать в объяснении.
- Часто спрашивают то, чего нет в реестре → кандидат в новые параметры.
- Спрашивают одно и то же разными словами → формулировка на карточке плохая.

Раз в неделю: кластеризовать вопросы, выделить топ-20 тем, разнести по трём
корзинам — «показать в интерфейсе» / «переписать текст» / «добавить параметр».

Хранятся только тексты вопросов, без привязки к человеку и его данным.

## 7.6 Микро-фидбек на понятность

92 параметра × 3 уровня глубины = 276 текстов. Какие не работают —
без обратной связи не узнать.

На карточке, ненавязчиво, после прочтения объяснения:

```
Понятно?   [ да ]  [ не очень ]
```

«Не очень» → предложить другой уровень глубины («объяснить проще?»)
и записать `{parameterId, depth, 'unclear'}`. Дальше видно, какие именно
тексты переписывать, а не гадать.

## 7.7 LLM как интервьюер

У проекта уже есть диалоговый слой — он может собирать качественный фидбек
лучше любой формы, потому что делает это в разговоре, а не анкетой.

Условия: **не чаще одного раза за сессию**, только если человек уже вовлечён
(задал минимум два вопроса), всегда легко отмахнуться.

> «Кстати — было что-то, что осталось непонятным? Я передам разработчику».

Ответы попадают в ту же корзину, что и вопросы. Это даёт формулировки живым
языком, которых не даст ни одна форма.

## 7.8 Публичные каналы

- **GitHub Issues** — естественный канал для технической аудитории.
  Исходники открыты, значит физик может не просто пожаловаться, а прислать PR
  с исправленной формулой. Это часть позиции проекта, а не только сбор багов.
- **Публичный changelog** — что починили и по чьей наводке. Отвечать на фидбек
  публично дешевле и полезнее, чем в личке.
- **Страница «известные расхождения»** — где мы знаем, что модель упрощена,
  и насколько. Проект о честности обязан признавать свои погрешности первым.

## 7.9 Цикл: фидбек → реестр → продукт

```
вопрос / жалоба / расхождение
        ↓
   кластеризация (раз в неделю)
        ↓
   ┌────────────┬──────────────┬───────────────┐
   ↓            ↓              ↓               ↓
показать    переписать    добавить        исправить
в сцене      текст        параметр         формулу
   ↓            ↓              ↓               ↓
        контент-база (Airtable) → продукт
```

Контент-база — то же место, где живут 92 параметра. Значит фидбек
не собирается в отдельную свалку, а сразу превращается в правку строки:
текст, формула, статус верификации.

## 7.10 Приоритизация

| Приоритет | Что | Реакция |
|---|---|---|
| **Критично** | расхождение в `[ТОЧНО]`-значении | проверить в течение суток, при подтверждении — снять тег до исправления |
| **Высоко** | верификационный тест не сходится у многих | искать системную причину |
| **Средне** | текст непонятен многим | переписать в ближайшем цикле |
| **Средне** | повторяющийся вопрос к LLM | вынести в интерфейс |
| **Низко** | пожелания по фичам | в бэклог, сверять с тезисом |

**Фильтр для любой просьбы о новой фиче:** работает ли она на тезис
«космос внутри тебя». Если нет — вежливое «нет», сколько бы раз ни просили.
Иначе проект расползётся обратно в 92 параметра и никогда не будет закончен.

## 7.11 Что реализуем когда

| Этап | Что включаем |
|---|---|
| **С первого дня** | самостоятельная аналитика, GitHub Issues, кнопка «число неверно» |
| **С первыми пользователями** | микро-фидбек «понятно?», сбор вопросов к LLM |
| **После сотни пользователей** | краудсорс верификации, LLM-интервьюер |
| **Постоянно** | публичный changelog, страница известных расхождений |

## 7.12 Ручной канал, который нельзя пропускать

Первые двадцать пользователей — **посмотреть вживую**, как они пользуются.
Пять человек с записью экрана и просьбой думать вслух дадут больше, чем
тысяча строк аналитики. Особенно на первых десяти секундах: если человек
не понял, что видит, — никакие метрики этого не объяснят.
